# Harness Roadmap

最終更新: 2026-10-08

## 目的

仕様から実装、検証、レビューまでを再現可能にし、ソフトテニスのルール変更や保存形式の変更を安全に行える状態を維持する。

## 品質ゲート

| ゲート | 合格条件 | 状態 |
| --- | --- | --- |
| G0 要件 | 対象、対象外、保存範囲、ルール根拠が明確 | 完了 |
| G1 設計 | MVVM、Repository、状態遷移、DB境界が明確 | 完了 |
| G2 タスク | 成果物と対応テストが分割されている | 完了 |
| G3 ローカル | format、analyze、unit/widget test成功 | ハーネス整備済み。変更ごとにローカルとCIで再検証 |
| G4 統合 | 画面導線、iOS/Android実操作、Watch実機同期 | Flutter導線はCI対象。MVPのiPhone 16／Pixel 8確認は完了。Watch切断・再接続の実機結果は別途記録が必要 |
| G5 PR | レビュー、CI、受け入れ条件、移行確認 | PR #14〜#22を`develop`へ統合済み。以後の変更もPR単位で継続 |

## 完了済み

- Flutter 3.47.2 / Dart 3.13.2の固定
- Riverpod、MVVM、Repository Patternの依存境界
- イベント履歴から再計算する得点ルールエンジン
- 3・5・7・9ゲームすべての試合単位デュース設定とファイナルゲーム
- サービス／レシーブ順、チェンジサービス／チェンジサイズ案内
- SQLite保存、未完了試合の再開、v1→v2移行、自分ペア設定
- 試合作成、得点、取消、得点理由、結果、履歴詳細、削除、期間別集計
- format、analyze、unit/widget、SQLite、integration testのハーネス
- 1st／2ndサービス、フォルト・ダブルフォルト、得点理由の候補制御と2段階取消
- ポイントを優先した得点表示
- SwiftUI製Watchコンパニオン、ローカル保存、編集権の引き渡し、同期スキーマv2、Dart／Swift共通ルールベクトル
- Watchビルド、Series 3向け`armv7k`、Swiftテスト、Watch同梱iPhoneアーカイブのCI検証
- 記録処理・画面・テストfixtureの共通化、未使用コードの削除、保存失敗・二重入力・完了後ロックの回帰テスト（Spec 003／PR #22）

## 継続して確認すること

- 実装・自動品質ゲートとPR統合は完了している。リリース前にiPhone／Androidの実操作とSeries 3を含むWatch実機で、切断中操作・再接続同期・復帰・署名付きアーカイブを確認し、結果を記録する。
- 有償の最新版ルールブックを入手した場合は、`docs/harness/rules.md`とDart／Swift両エンジンの期待値を照合する。

## 実行規則

1. 変更前にSpec、Design、Tasksを確認する。
2. 実装と、それを守るテストを同じPRへ含める。
3. `./scripts/verify.sh` を成功させる。
4. 画面変更では統合テストと対象OSの確認を行う。Watchの通信・オフライン動作は実機で確認する。
5. 仕様判断はSpecまたはADRへ記録する。
