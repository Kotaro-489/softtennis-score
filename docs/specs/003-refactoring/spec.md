# Spec 003: 記録処理とテストのリファクタリング

## 目的

重複処理・未使用コードを減らし、関数の責務を読み取りやすくする。Spec 001・002の操作、得点規則、保存済みデータの互換性は維持する。

## 受け入れ条件

- 得点・フォルト・取消・理由設定の保存、保存中の操作制御、版番号更新を共通化する。
- 保存に失敗した編集は保存済み試合へ反映せず、再読み込み後に再編集できる。
- 完了通知は保存後に行い、完了試合の追加編集を受け付けない。
- 得点画面の表示順・文言・ボタンサイズを保ち、重複する非同期処理を共通化する。
- テスト用試合・Repositoryを共通化し、重複するテストは上位互換の検証へ統合する。
- 説明コメントは関数に付け、処理途中の行コメントを残さない。
- SQLiteのスキーマ・JSON・Watch同期スキーマを変更しない。

## 対象外

新機能、ルール変更、ライブラリ更新、WatchConnectivity通信方式の変更は含めない。
