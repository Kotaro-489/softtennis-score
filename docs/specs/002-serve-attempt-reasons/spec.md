# Spec 002: サービス回数と得点理由制御

## 目的

得点操作の速さを維持したまま、現在のサービスが1stか2ndかを明示し、サービス状況と矛盾する得点理由を選択できないようにする。

## 受け入れ条件

- [x] 現在の1st／2ndサービスを常に確認できる
- [x] 1stフォルトで得点を変えずに2ndへ移行できる
- [x] 2ndフォルトでレシーブ側へ自動加点し、ダブルフォルトとして保存できる
- [x] 得点側、サービス側、サービス回数に整合する理由だけを表示・保存できる
- [x] 2ndで終了したポイントの取消後は2ndへ戻り、もう一度の取消で1stへ戻る
- [x] 未完了試合を2nd状態のまま保存・再開できる

## 対象外

- 1st成功率、1st／2nd別ポイント取得率などの集計表示
- 完了試合の編集

## 保存項目

試合の現在サービス回数と、各ポイントが終了したサービス回数を既存のJSON payloadへ追加する。旧データで項目が存在しない場合は1stとして扱う。
